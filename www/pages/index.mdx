<Section id="performance" eyebrow="Performance" title="Parse once. Build in parallel.">

doc-kit parses your docs once and builds every output from that one parse. So JSON, the search index and LLMs.txt add only a little to the time the site takes on its own.

<Performance>

- **Works in chunks.** The heavy stages split the work across a pool of worker threads, and the site and JSON are written chunk by chunk.
- **Runs side by side.** Outputs that don't depend on each other run at the same time, all from the same API entries.
- **Frees as it goes.** A stage's result is dropped once its last reader is done, so memory is reclaimed while the rest of the build runs.

</Performance>

</Section>

<Section id="outputs" eyebrow="One source, many formats" title="Write it once. Every output agrees.">

Document an API in Markdown, where a heading is a signature, a list holds typed parameters and a comment records history. Use MDX for pages that need components, or let the TypeDoc plugin write the Markdown from your TypeScript and JSDoc. <span class="dk-nowrap">doc-kit</span> parses it all once into typed API entries and builds every output from them.

<Section id="features" eyebrow="Features" title="Made for API reference.">

<Features>
  <Feature art="api" title="Knows a method when it sees one" href="/writing-docs">
    Classes, methods, events, properties and constructors are recognized by how you write their headings. Parameters, defaults, return values, stability and history become data, not decoration.
  </Feature>
  <Feature art="types" title="Types that link themselves" href="/writing-docs#types-that-link-themselves">
    Write \{string|Buffer\} and each type links to its docs, found in your type map first, then on MDN for JavaScript built-ins and Web APIs, then in your own pages.
  </Feature>
  <Feature art="islands" title="Static pages, interactive islands" href="/generators/html#client-side-navigation">
    Pages are rendered to static HTML at build time and load <Fact name="javascript" /> of gzipped JavaScript up front. The search box, theme switch and sidebar hydrate once the browser is idle, and code blocks the first time you reach for one. Links between pages swap the content in place.
  </Feature>
  <Feature art="ai" title="For people and for models" href="/generators/llms-txt">
    The search index, a sitemap and LLMs.txt, in a short and a full version, come out of the same build as the site. People and models read the same docs.
  </Feature>
  <Feature art="theme" title="Make it yours" href="/customization">
    Swap any part of the page for your own component, use components in MDX, restyle it with CSS or hand Vite your plugins. This site is <span class="dk-nowrap">doc-kit</span>, themed.
  </Feature>
  <Feature art="typescript" title="TypeScript and JSDoc, too" href="/packages/typedoc">
    The experimental <span class="dk-nowrap">@doc-kit/typedoc</span> plugin turns TypeScript and JSDoc-annotated JavaScript into Markdown, so your reference lives next to your guides.
  </Feature>
</Features>

</Section>

<Section id="start" eyebrow="Getting started" title="Docs in three steps.">

<Steps>

<Step title="Install">

The CLI and the generators that build the site.

```bash displayName="npm"
npm i -D @doc-kit/cli @doc-kit/generator-react
```

```bash displayName="pnpm"
pnpm add -D @doc-kit/cli @doc-kit/generator-react
```

```bash displayName="yarn"
yarn add -D @doc-kit/cli @doc-kit/generator-react
```

```bash displayName="bun"
bun add -d @doc-kit/cli @doc-kit/generator-react
```

</Step>

<Step title="Write">

Markdown, with headings written like signatures and lists like parameters. Or let @doc-kit/typedoc write it from your TypeScript or JSDoc.

```md
# Kittens

The `kittens` module adopts, feeds, and pets kittens.

## `kittens.pet(kitten[, times])`

- `kitten` {Kitten} The kitten to pet.
- `times` {number} **Default:** `1`.
- Returns: {boolean} Whether it purred.
```

</Step>

<Step title="Generate">

The site and its search index, then a local preview.

```bash
npx doc-kit generate -t html -t orama-db -i "docs/*.md" -o out
npx serve out
```

</Step>

</Steps>
